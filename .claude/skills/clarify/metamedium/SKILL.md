# 메타매체: 내용 vs 형식 렌즈

**내용**(무엇을 말하고/만드는지)과 **형식**(전달되는 매체/구조)을 구분하여, 실제 레버리지가 내용 최적화에 있는지 새로운 형식 발명에 있는지를 드러냅니다. Alan Kay의 메타매체 개념에 기반합니다.

> "관점의 전환은 IQ 80점의 가치가 있다." — Alan Kay

## 핵심 개념

대부분의 사람들은 **내용**만 바꾼다 — 무엇을 말하고, 쓰고, 만드는지. 진짜 레버리지는 **형식**을 바꾸는 데 있다 — 매체, 포맷, 구조 자체를.

| | 내용 (무엇을) | 형식 (어떻게/매체) |
|--|----------------|-------------------|
| 예시 | LinkedIn 게시글 작성 | 클라이언트 작업에서 게시글을 자동 생성하는 도구 구축 |
| 예시 | 단위 테스트 수동 작성 | 타입 시그니처에서 테스트를 생성하는 도구 구축 |
| 예시 | 워크숍 진행 | 참가자가 결과물을 함께 만드는 포맷 발명 |
| 레버리지 | 선형 — 각 작업이 하나의 결과물 | 지수적 — 새로운 형식은 무한한 내용을 가능하게 함 |

## 사용 시점

- 프로젝트를 계획 중이며, 결과물을 최적화할지 프로세스를 최적화할지 불확실할 때
- 내용 최적화를 반복하다 수확 체감에 빠졌을 때
- 무언가를 만들면서 형식 수준의 변화가 더 큰 레버리지를 줄지 확인하고 싶을 때
- "더 많이 같은 것"이 맞는지, "구조적으로 다른 것"이 맞는지 평가할 때

요구사항 명확화는 **vague** 스킬을 사용하라. 전략 사각지대 분석은 **unknown** 스킬을 사용하라.

## 프로세스

**2단계의 분기 질문에는 항상 AskUserQuestion 도구를 사용할 것** — 내용/형식 선택을 일반 텍스트로 묻지 않는다.

### 1단계: 식별 및 레이블링

사용자의 현재 작업, 계획, 태스크를 읽는다. 각 구성 요소를 내용 또는 형식으로 분류한다:

```
[CONTENT] AI 컨설팅에 관한 블로그 게시글 작성
[FORM]    컨설팅 회고록을 블로그 게시글로 변환하는 파이프라인 구축
[CONTENT] 새 API 엔드포인트 배포
[FORM]    스키마에서 엔드포인트를 자동 생성하는 코드젠 도구 구축
[CONTENT] 불안정한 테스트 수정
[FORM]    설계 단계에서 불안정 테스트를 방지하는 테스트 인프라 구축
```

레이블링 결과를 간략한 진단으로 사용자에게 제시한다.

### 2단계: 분기점 제시

AskUserQuestion을 사용하여 내용/형식 선택을 제시한다:

```
questions:
  - question: "This is currently [CONTENT/FORM]-level work. Where should effort go?"
    header: "Level"
    options:
      - label: "Proceed with content"
        description: "Optimize within the current form — faster, lower risk"
      - label: "Explore form change"
        description: "What if the medium/structure itself changed? Higher leverage"
      - label: "Content now, note form"
        description: "Do the content work, but flag the form opportunity for later"
    multiSelect: false
```

### 3단계: 분기 처리

**"Proceed with content" 선택 시**: 그대로 진행한다. 향후 참고를 위해 출력물에 `Form Opportunity` 항목을 포함한다.

**"Explore form change" 선택 시**: 형식 대안 2~3개를 생성한다. 각 대안에 대해:
- 새로운 형식이 구체적으로 어떤 모습인지
- 새롭게 가질 특성 (자동화, 반복 가능, 확장 가능, 조합 가능)
- 형식을 검증할 수 있는 최소 실행 버전

**"Content now, note form" 선택 시**: 내용 작업을 진행한다. 출력물에 형식 기회를 추가한다.

### 출력 형식

모든 결과물에 덧붙이거나 단독으로 제시한다:

```markdown
## 내용/형식 분석

**현재 작업**: [설명]
**분류**: [CONTENT / FORM]

### 형식 기회
| | 상세 |
|---|--------|
| **대안 형식** | [어떤 모습일지] |
| **새로운 특성** | [현재 형식이 할 수 없는 것을 무엇이 가능하게 하는지] |
| **최소 검증** | [검증할 가장 작은 버전] |
| **상태** | [탐색 중 / 향후 메모 / 해당 없음] |
```

## 메타매체 질문

막혔거나 최적화의 수확이 체감될 때:

> **"이 문제를 사라지게 만들 새로운 형식/매체는 무엇인가?"**

예시:
- 게시글을 더 쓰는 데 막혔다? → 클라이언트 작업을 자동으로 게시글로 변환하는 포맷
- 테스트 커버리지가 정체됐다? → 타입 시그니처에서 테스트를 생성하는 도구
- 온보딩이 너무 느리다? → 코드베이스가 스스로를 가르치는 자기 주도형 포맷

## 안티패턴

- 형식 변화가 가능한데도 모든 작업을 내용 최적화로만 처리하기
- 형식이 병목인데 "더 나은 내용"을 만들기
- 현재 매체/포맷이 고정되어 있고 내용만 바꿀 수 있다고 가정하기
- 점진적인 내용 개선을 형식 발명과 혼동하기

## 규칙

1. **항상 레이블링**: 작업을 내용 또는 형식으로 태그한다
2. **내용도 괜찮다**: 모든 것이 형식 변화를 필요로 하지는 않는다. 단, 항상 선택지를 메모한다
3. **형식이 힘을 만든다**: 새로운 형식 = 새로운 매체 = 지수적 레버리지
4. **코드는 메타매체다**: 코딩 능력은 형식을 바꾸는 능력이다
5. **만져봐야 이해된다**: 형식을 바꿔봐야 왜 그렇게 설계되었는지 알 수 있다
