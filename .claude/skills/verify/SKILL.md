# 변경 사항 검증

코드 변경 후 사용자보다 먼저 오류를 잡아내기 위해 실행한다. 이 스킬은 순차적 검증 파이프라인을 정의한다.

## 파이프라인

각 단계를 순서대로 실행한다. 첫 번째 실패 지점에서 멈추고, 수정한 뒤 파이프라인을 다시 시작한다.

### Step 1: 정적 분석

수정된 모든 파일에 대해 언어별 분석기를 실행한다.

```bash
# Dart/Flutter
dart analyze <changed_files>

# TypeScript
npx tsc --noEmit

# Python
mypy <changed_files>
```

### MUST
- 주요 대상 파일뿐 아니라 수정된 모든 파일에 분석을 실행한다.
- 새로운 **에러**는 블로커로 취급한다 — 진행 전에 수정한다.
- 변경된 라인에서 발생한 새로운 **경고**는 수정해야 한다. 기존에 있던 경고는 무시해도 된다.

### MUST NOT
- 분석을 통과시키기 위해 인라인 무시 주석(`// ignore:`, `// eslint-disable`)으로 경고를 억제하지 않는다.

### Step 2: 의존성 체인

함수 시그니처, 클래스 생성자, 또는 인터페이스 메서드가 변경된 경우 모든 호출 지점이 업데이트되었는지 확인한다.

```bash
# 변경된 함수/클래스의 모든 호출 지점 찾기
grep -rn "FunctionOrClassName" lib/
```

### 체크리스트
- [ ] 생성자 파라미터 추가/제거 → 모든 인스턴스화 지점 업데이트
- [ ] 인터페이스 메서드 시그니처 변경 → 모든 구현체 업데이트
- [ ] 메서드 반환 타입 변경 → 모든 호출 지점에서 새 타입 처리
- [ ] DI 등록이 업데이트된 생성자와 일치하는지 확인

### MUST
- 전체 호출 체인을 추적한다: 인터페이스 → 구현체 → DI 등록 → 사용 지점.
- 클래스에 파라미터가 추가된 경우 DI 모듈과 팩토리 메서드를 확인한다.

### Step 3: Import 정리

변경 후 import가 올바른지 확인한다.

```bash
# Dart: 분석기가 사용되지 않는 import를 경고로 잡아냄
dart analyze <file> | grep "unused_import"
```

### 체크리스트
- [ ] 수정된 파일에 사용되지 않는 import 없음
- [ ] 새로운 의존성이 필요한 곳에 import됨
- [ ] 순환 import가 발생하지 않음

### Step 4: 컴파일 확인

프로젝트가 오류 없이 컴파일되는지 확인한다.

```bash
# Dart/Flutter
flutter build apk --debug 2>&1 | tail -20
# 또는 간단한 확인:
dart analyze lib/

# TypeScript
npx tsc --noEmit

# Go
go build ./...
```

### MUST
- 여러 파일이나 레이어에 걸친 변경이 있을 때 전체 컴파일 확인을 실행한다.
- 단일 파일 변경의 경우 정적 분석(Step 1)으로 충분하다.

### Step 5: 동작 보존 확인

리팩터링(의도적인 동작 변경이 없는 경우) 시 변경이 동작을 보존하는지 확인한다.

### 체크리스트
- [ ] 새로운 제어 흐름 경로 추가 없음 (새로운 if/else/switch 분기 없음)
- [ ] 함수 호출 순서 변경 없음 (의도적인 경우 제외)
- [ ] 반환 타입 또는 값의 의미 변경 없음
- [ ] 사이드 이펙트 추가 또는 제거 없음 (DB 쓰기, 네트워크 호출, 상태 변경)
- [ ] 공개 API 표면 유지 (동일한 메서드명, 동일한 파라미터 타입)

### MUST
- 위 체크리스트를 기준으로 수정된 각 파일의 diff를 검토한다.
- 테스트가 존재하는 경우 실행한다: `flutter test`, `dart test`, `npm test` 등.

### MUST NOT
- "단순한" 리팩터링이라고 이 단계를 건너뛰지 않는다 — 단순한 변경도 문제를 일으킨다.

## 빠른 참조

```
Step 1: dart analyze <files>         → 에러 수정
Step 2: 변경된 API의 호출 지점 grep → 모두 업데이트 확인
Step 3: import 확인                  → 미사용 없음, 누락 없음
Step 4: flutter build / tsc          → 깨끗하게 컴파일
Step 5: diff 검토                    → 동작 보존 확인
```

## 각 단계를 실행해야 하는 경우

| 변경 유형 | 실행할 단계 |
|-------------|-------------|
| 단일 파일 편집 | 1, 3 |
| 시그니처 변경 (파라미터, 반환 타입) | 1, 2, 3 |
| 멀티 파일 리팩터링 | 1, 2, 3, 4, 5 |
| DB 스키마 변경 | 1, 2, 3, 4 |
| 새로운 기능 | 1, 3, 4 |
