- **제약**: 기능·연출 위주 / 새 콘텐츠(글·그림) 제작 최소 / 1인 개발

## 1. 배경과 목표

### 핵심 가치 사슬

> **① 이야기를 재밌게 풀어낸다 → ② 유적지에 호기심을 갖는다 → ③ 풍부한 관광 경험으로 이어진다**

①이 엔진, ②가 전환점, ③이 보상이다. 이번 개선은 **①과 ②를 한 흐름으로 묶어** 강화한다.

### 현재 상태 진단 (코드 기준)

- **① 읽는 재미**: 채팅 뷰어가 "탭 → 즉시 말풍선 등장"뿐이라 기계적. 메신저 메타포를 표방하면서 메신저의 생동감(타이핑·페이싱·햅틱)을 쓰지 않는다. 진행도·길이 가늠 장치도 없다.
- **② 호기심 전환 (가장 약한 고리)**: 제품 명제가 "이야기가 장소 호기심을 만든다"인데, 실제 흐름은 *이야기 끝 → 버튼 → 정보 시트(주소·시간·요금)*로 점프한다. 정보는 주지만 "가보고 싶다"는 감정을 만들지 못한다. 무대 화면이 행정 안내문에 가깝다.

### 목표

읽는 동안 살아있는 메신저 느낌으로 몰입시키고(①), 완독 순간 감정을 끊지 않고 무대로 넘기며(연결), 무대 화면을 "가보고 싶다"를 만드는 호기심 페이지로 재설계한다(②). **새 글·그림 0, 기존 데이터 + 연출만으로 구현한다.**

### 선택된 접근법

3개 후보(A 연출 중심 / B 여정 재설계 / C 몰입 엔진 본격화) 중 **B**를 채택. 가장 약한 고리 ②를 정면으로 강화하면서 ①도 함께 끌어올리고, "기능·연출 + 기존 데이터" 제약에 깔끔히 들어온다.

## 2. 전체 여정

```
[이야기 목록] → [채팅 뷰어] ───────────→ [에필로그 비트] → [무대 화면]
                 (① 몰입 강화)            (연결 다리)      (② 호기심 점화 IA)
                 타이핑·햅틱·진행도        "끝. 하지만        사진 먼저 → 「제목」의
                                          그 무대는…"        무대 → 개요를 호기심
                                                            카피로 → 실용정보 → 주변
```

## 3. 기능 설계

### 3.1 ① 채팅 몰입 (연출·인터랙션)

대상: `view/story/screen/screen_chat.dart`

- **타이핑 인디케이터**: 인물(chat) 말풍선이 뜨기 직전, 그 인물 색/아바타로 `● ● ●` 점 애니메이션을 잠깐 보였다가 텍스트로 크로스페이드한다. **나레이션(narration) 메시지에는 적용하지 않는다**('사람이 치는 중'이 아니므로).
- **햅틱**: 탭으로 진행할 때 `HapticFeedback.lightImpact()`.
- **진행도 바**: 앱바 아래 얇은 바로 `읽은 말풍선 수 / 전체 말풍선 수`를 표시. 이야기 길이·끝을 가늠하게 해 몰입·완독률을 높인다.
- **자동 스크롤**: 새 말풍선이 삽입되면 최신 메시지로 부드럽게 스크롤한다.
- **탭 힌트 다듬기**: 회색 "화면을 탭해 이야기를 이어가세요" → 은은하게 깜빡이는 힌트로(초반/입력이 멈췄을 때 위주).

**구현 원칙**: 전부 뷰 레이어 연출. ViewModel의 `visibleCount` / `revealNext` / `isCompleted` 로직은 그대로 두고, 타이핑 비트·진행도·스크롤·햅틱만 화면에서 처리한다. 타이핑 비트는 말풍선 위젯 내부의 자기완결 애니메이션으로 구현해 VM과 무관하게 둔다.

### 3.2 에필로그 연결 비트 (다리)

대상: `screen_chat.dart`의 완독 상태(`isCompleted`) 영역 — 기존 `_StageButton`을 대체.

현재의 단일 버튼을 감정을 끊지 않는 **닫는 비트**로 교체한다.

```
            ─  끝  ─                  (이야기 종료 마크, fade-in)

   이야기는 여기서 끝납니다.            (이야기 무관 고정 카피)
   하지만 그 무대는 지금도
   경주에 남아 있습니다.

   [  「서출지」의 무대 보러가기  ]     (유적지명 site.name 만 끼움)
```

- 마지막 말풍선 뒤로 카드가 부드럽게 등장한다(기존 fade+slide 토큰 재사용).
- 카피는 **이야기 무관 고정 문구** + 유적지명(`site.name`)만 끼워넣는다 → 새 콘텐츠 0.
- 버튼 → 무대 화면. 진입 시 무대의 대표 사진이 **fade**로 떠오르며 "장면이 실제 장소로" 느낌을 연결한다. (Hero 전환은 사진 로드 타이밍 변수가 있어 **기본은 fade**, 여유 시 Hero 추가 — 선택 사항.)

### 3.3 ② 무대 화면 재설계 (호기심 점화 IA) — 핵심

대상: `view/heritage/screen/screen_stage.dart`의 `_DetailContent`

같은 TourAPI 데이터를 **순서와 프레이밍만** 바꿔 "정보 시트 → 호기심 페이지"로 전환한다.

**Before (현재 순서)**
```
사진 → 제목+배지 → 주소/시간/휴무 → "지도앱에서 검색하세요"(텍스트)
     → 개요 → 갤러리 → 주변 → 출처
```

**After (호기심 우선)**
```
▓▓ 큰 대표사진 (풀폭, 하단 그라데이션 스크림) ▓▓
   「서출지, 까마귀가…」의 무대        (방금 읽은 이야기명 story.title)
   서 출 지            [유네스코]      (유적지명 크게 + 배지)
──────────────────────────────
   이곳은 신라 소지왕이 …             (개요 overview 를 '이곳은…' 리드 카피로
   (편안한 행간, 호기심 카피 톤)         먼저 = 점화 지점)
──────────────────────────────
   ▸ 가는 길 · 실용 정보 (카드)
      📍 주소            [지도에서 보기]  (url_launcher 실제 링크)
      🕘 운영시간 / 휴무 / 요금
──────────────────────────────
   갤러리  ▢ ▢ ▢ →                    (기존)
   주변에 더 · 가까운 명소들            (기존, '코스' 호기심 보조)
   이야기 출처 · 삼국유사 …             (기존, 신뢰도)
```

바뀌는 것:
- **대표 사진을 더 크게 + 하단 그라데이션 스크림** → 그 위에 "「이야기명」의 무대"(있을 때) + 유적지명을 얹어 영화 포스터 느낌.
- **개요(overview)를 맨 앞 리드 카피로** 끌어올림 = 호기심 점화. (TourAPI 데이터 그대로, 위치만 이동)
- **실용정보(주소·운영시간·휴무·요금)는 '가는 길' 카드로 묶어 2순위.** "지도에서 보기"는 실제 지도앱 링크(`url_launcher`, `detail.address` 쿼리).
- 갤러리·주변·출처는 유지.

**구현 원칙**: `_DetailContent`의 레이아웃·순서·카피만 재구성. `StageViewModel` · `HeritageDetailModel` · TourAPI 호출 로직은 무변경. 지도 링크는 모델 변경 없이 `detail.address` 쿼리로 열어 도메인 영향 0.

## 4. 기술 영향 · 범위

### 손대는 파일 (전부 view 레이어)

| 파일 | 변경 | 종류 |
|---|---|---|
| `view/story/screen/screen_chat.dart` | 타이핑 인디케이터·햅틱·진행도 바·자동스크롤·에필로그 카드 | 연출/레이아웃 |
| `view/heritage/screen/screen_stage.dart` | `_DetailContent` IA 재구성·사진 스크림·실용정보 카드·지도 링크 | 레이아웃/카피 |
| `view/app/app_motion.dart` | 타이핑 비트 duration 토큰 1개 추가 | 토큰 |
| `view/story/widget/` *(신규, 선택)* | 타이핑 인디케이터·진행도 바 위젯 분리 | 신규 위젯 |
| `pubspec.yaml` | `url_launcher` 의존성 추가 | 설정 |

### 절대 변경하지 않는 것

ViewModel(`visibleCount` / `revealNext` / `isCompleted` / `load`), 도메인 모델, repository, data 레이어, TourAPI 호출 로직. → 기능·데이터 흐름 무변경, 순수 표현 계층 작업.

### 새 의존성

`url_launcher` (지도앱 열기용, 검증된 표준 패키지).

## 5. 리스크 · 대응

- **타이핑 비트 ↔ AnimatedList 삽입/자동스크롤 타이밍 충돌**: 타이핑은 말풍선 위젯 내부 자기완결 애니메이션으로 처리(VM 무관), 스크롤은 삽입 후 1프레임 뒤 `animateTo`.
- **지도 링크 좌표 부재**: 모델 변경을 피하려 `detail.address` 텍스트 쿼리로 지도앱 오픈(핀 정확도는 주소 수준, 충분).
- **url_launcher 실패 / 지도앱 없음**: 실패 시 스낵바로 안내(조용히 무시하지 않음).
- **무대 대표 사진 없음(`firstImageUrl == null`)**: 기존 폴백(흙빛 면 + 아이콘) 유지, 그 위에 텍스트를 얹는다.

## 6. 범위에서 제외 (YAGNI)

- 효과음 / BGM (에셋 필요 → '콘텐츠 최소' 제약과 충돌)
- 이어보기 / 읽기 진행도 저장 (접근법 C 영역)
- 찜 / 코스 계획 (③ 보상 영역, 다음 라운드)
- Hero 전환 (여유 시 옵션, 기본은 fade)

## 7. 검증

- 변경 후 `flutter analyze` 통과.
- 채팅 완독 → 에필로그 → 무대 플로우 수동 확인(에뮬레이터): 타이핑 비트·진행도·자동스크롤·지도 링크 동작.
- 기존 위젯/단위 테스트에 영향 없음 확인(표현 계층만 변경).

## 8. 핵심 가치 정합성

- **① 읽는 재미**: 타이핑·햅틱·진행도·자동스크롤로 "살아있는 메신저" 몰입.
- **② 호기심 전환**: 에필로그 연결 + 무대 화면을 호기심 점화 IA로 재설계해, 제품 명제의 가장 약한 고리를 직접 보강.
- **제약 준수**: 새 글·그림 0, 기존 TourAPI/콘텐츠 데이터 재활용, view 레이어 한정으로 기능·데이터 흐름 무변경.
